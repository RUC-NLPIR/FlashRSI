# FlashRSI project page — direction cards

## Shared form assumptions

- **Narrative role:** research landing page / public benchmark index; it should answer “what is FlashRSI?”, “what can I run?”, and “where are the results?” in one scroll.
- **Audience distance:** laptop first (1 m), mobile second; dense data blocks need strong hierarchy and 14px+ body type.
- **Visual temperature:** credible, energetic, and open about what is measured versus what still needs logs.
- **Content capacity:** hero, four proof points, one results view, surface catalog, and a future log-analysis entry point.
- **Visual motif:** an agent harness is a versioned resource system, so snapshots, trajectories, and benchmark scores become visible objects.

## Six candidates

### 1A · Benchmark Atlas / best-fit research UI
- **Logic/source:** Best designer direction inspired by a restrained research portal and the information density of Agents’ Last Exam.
- **Borrowed rules:** sticky top navigation, compact pill links, high-contrast serif/sans hierarchy, catalog cards, result table as a first-class section.
- **Hero material:** `framework-overview.jpg` framed as an “evolution map”; real README result values appear in a compact table.
- **Skeleton:** centered hero → proof stats → result explorer → three catalog columns → CTA.
- **Bold move:** one oversized benchmark ribbon that turns the result table into a navigable atlas.
- **Form from content:** FlashRSI joins algorithm × harness × benchmark, so the page exposes those dimensions as a map.

### 1B · Electric operator console / best-fit technical
- **Logic/source:** Best designer direction for a system that feels live and inspectable.
- **Borrowed rules:** deep navy canvas, electric cyan signal lines, split-screen hero, terminal-like evidence panels, dense heatmap.
- **Hero material:** existing electric wordmark and `slot-machine.gif` as a “run settles on a combination” moment.
- **Skeleton:** command header → live experiment board → heatmap → supported surface → trace handoff.
- **Bold move:** an animated-looking (CSS) candidate lane showing Snapshot → rollout → score.
- **Form from content:** the framework’s real unit is a run record, so the hero behaves like a run console.

### 1C · Research field notes / editorial reference
- **Logic/source:** Reality reference direction based on editorial research journals and paper landing pages.
- **Borrowed rules:** warm paper background, serif display, marginal labels, long-form narrative, charts as evidence rather than decoration.
- **Hero material:** `slot-machine.gif` embedded as a specimen plate; a large serif statement anchors the page.
- **Skeleton:** masthead → “why this exists” essay → evidence plate → methods / benches / harnesses notebook → result excerpts.
- **Bold move:** a vertical “experiment ledger” running through the page with dated entries.
- **Form from content:** Snapshots and lineage are versioned research notes, so the site reads like an evidence notebook.

### 2A · Minimal benchmark index
- Thin white canvas, single giant metric, filterable cards.
### 2B · Split-screen lab report
- Left narrative column, right live chart board, no sidebar.
### 3A · Data poster
- Large poster-like typography, short sections, result table as the hero.
### 3B · Reference graph
- Node-link motif for algorithms / harnesses / benches, with results as edge labels.
