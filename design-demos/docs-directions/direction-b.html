Guide / first run

Make the agent better, keep the evidence.

A practical guide to evolving instructions, skills, and harness resources while preserving the native execution path that gives them meaning.

shellquickstart
$ flashrsi run \
  --config examples/quickstart.yaml \
  --model gpt-5-mini \
  --worker-model gpt-5-mini

→ writes snapshots, trajectories, and result.json
GuideIntegrationsDevelopmentReference

01. Configure the roles

Target and Worker are independent. The Target completes tasks with the current Snapshot; the Worker proposes edits or changes candidate files.

agent.llmTargetmodel, endpoint, turns, runtime
algorithm.workerWorkerLLM or Agent editing role
benchmarkEvidencetasks, split, grader, environment
runReceiptoutput directory and mode
check-only: validate dependencies and data before a model call. It does not authenticate a remote model.

02. Evaluate a frozen Snapshot

Run flashrsi evaluate --snapshot /path/to/snapshot.json to test a selected or intermediate candidate without creating a Worker or continuing search.

03. Pick a method

Algorithms share checkout, rollout, scoring, and records. Their proposal schedule, feedback policy, and adoption rule stay independent.

methodscopesearch
SkillOptskillsfast / slow updates
OPROinstructionsscored history
AHEharnesssuccessive edits

04. Understand the Snapshot

FlashRSI maps a harness to a tagged resource tree. The algorithm edits a scoped view; the complete candidate is executed by the native harness and graded by the benchmark.
