## OTHERS
[of-00001] helpful=94 harmful=0 :: Return only the short answer token as the sole output — no preamble, explanation, hedging, or parenthetical elaboration.
[rd-00002] helpful=93 harmful=0 :: Keep all chain-of-thought and justification internal; never leak reasoning into the answer field, which is reserved strictly for the final extracted answer.
[ec-00003] helpful=94 harmful=0 :: Treat output-format compliance as part of correctness: under exact-match evaluation the full output string is compared against the ground-truth token, so any extra tokens convert a substantively correct answer into a zero.
[misc-00004] helpful=0 harmful=0 :: For 'Who was X?' questions over an encyclopedia passage, answer with the short defining appositive ('X is a ...') rather than the richest or most detailed biographical sentence; select the minimal complete descriptor and stop there — extra details that are factually true would still score zero under exact-match.
[misc-00005] helpful=6 harmful=2 :: For identity questions ('who', 'what man', 'what person'), extract the fullest/formal name variant exactly as it appears in the source's defining appositive, not the abbreviated or colloquial short form. A passage title is often an abbreviated label, while the full name lives in the body's first sentence; under exact-match, 'Paul Simon' and 'Paul Frederic Simon' are distinct tokens, so prefer the fullest name variant present in the context over world-knowledge-based short forms.
[m-00006] helpful=10 harmful=1 :: For multi-hop 'year' questions, extract the year from the target entity's own entry, never from the earlier hop's year — the first hop's year (e.g., Oldboy's 2003) is a designed distractor that yields a wrong token under exact match.
[m-00007] helpful=4 harmful=0 :: When a hop matches multiple candidates that share one entity (e.g., two films starring Moon Chae-won), reject the single-entity distractor by verifying the second entity also satisfies the full predicate from the earlier hop (e.g., debut in Oldboy), not just one overlapping entity.
[m-00008] helpful=0 harmful=0 :: Disambiguate near-identical title variants before chaining (2003 Korean 'Oldboy' vs 2013 American remake); only the variant carrying the required co-occurrence link (the debut actor) is a valid hop source.
[misc-00009] helpful=0 harmful=2 :: For 'what sport/occupation does X and Y participate in/do?' questions, extract the shared descriptor noun phrase verbatim from both entities' defining appositives (e.g., 'alpine ski racer'), not the abstract category or sport noun ('alpine skiing', 'skiing'). The question word may invite a category answer, but under exact match the ground truth is the literal descriptor phrase; prefer character-for-character verbatim extraction over semantic normalization.
[m-00010] helpful=6 harmful=0 :: For binary yes/no multi-hop questions, independently verify that every entity named in the question satisfies the predicate against its own context entry; answer 'yes' only if all listed entities satisfy it, 'no' if any fails, then emit the bare token ('yes'/'no') with no preamble or elaboration.
[misc-00011] helpful=24 harmful=4 :: For questions labeled 'multi-hop', first check whether the target answer phrase already appears verbatim in the question text or within a single context passage; when it does (e.g., 'traditional topping for St. Louis-style pizza' in the Provel passage), extract the shortest exact-match span and emit it bare rather than performing any hops. The 'multi-hop' label does not guarantee chaining is required — co-occurrence of the predicate and its object in one passage means direct verbatim extraction is sufficient and optimal under exact match.
[m-00012] helpful=8 harmful=0 :: When the target attribute string (e.g., a location like 'Hawaii') appears in multiple context entities, read it from the entity that satisfies the earlier hop's explicit relational predicate (e.g., 'partnered with' -> The Tetris Company), not from the first passage merely containing that string. The correct entity is fixed by the predicate, not by the attribute's co-occurrence; unrelated entities sharing the same attribute (e.g., Tetris Online also being Hawaii-based) are distractors that can yield the right token for the wrong reason.

[misc-00014] helpful=0 harmful=0 :: For 'often called what?' / 'known as what?' questions, the answer is a quoted epithet/nickname phrase inside the subject's own entry (e.g., 'Often called the "dean of science fiction writers"'); extract the quoted phrase verbatim without the surrounding quotes and emit it bare as the sole token.
[m-00015] helpful=0 harmful=0 :: When a bridging/attribution passage lists multiple co-equal values joined by 'and' (e.g., 'produced by Joseph E. Levine and Richard P. Under exact match a multi-value string is a guaranteed zero, and the first/primary-listed value is the safe verbatim pick.
[m-00016] helpful=0 harmful=1 :: For 'which X is older/younger?' comparative-age questions, extract each named entity's birth year/date from its own context entry (not a distractor passage), compare the values numerically, and emit the name of the entity with the earlier date (older) or later date (younger) as a bare token. [misc-00017] helpful=1 harmful=0 :: Extend verbatim extraction beyond [misc-00011]'s 'single passage' precondition: when a 'multi-hop' question ends in a fill-in-the-blank predicate clause ('...it is used in the teaching of what?'), the answer token may recur in several passages (e.g., 'singing' as 'singing teacher', 'use in singing'). Anchor on the sentence whose verb+prepositional construction mirrors the question's terminal clause ('It is used in the teaching of singing') and emit that grammatical object as the bare token. The token's recurrence across passages is not a cue to hop; skip chaining whenever the full predicate phrase co-occurs with its object in one passage.
[m-00018] helpful=2 harmful=1 :: For 'who wrote/created X' questions resolved by an explicit 'written by'/'directed by' attribution, emit the name exactly as it appears in that attribution (e.g., 'Ian Maxtone-Graham'), NOT the fuller name variant from the person's own entry (e.g., 'Ian Howes Maxtone-Graham'). [misc-00019] helpful=0 harmful=0 :: For positional/ordinal questions ('which place in order of released studio albums/singles...'), first locate the containing entity (album) via the track/song's own entry, then read the ordinal directly from that entity's own entry's explicit ordinal phrase (e.g., 'the thirteenth solo studio album by Paul McCartney') and emit it bare. Do not count through a release series or chain past the target entity's entry — the ordinal is stated verbatim and is the exact-match token.
[misc-00020] helpful=2 harmful=0 :: HotpotQA normalization strips leading articles ('the'), so when the ground-truth token carries a leading article (e.g., 'the thirteenth'), emitting the bare form ('thirteenth') is a safe exact-match token (exact_match and f1 both 1.0). Do not treat omission of the article as a failure and do not spend effort matching it.
[misc-00021] helpful=1 harmful=0 :: For binary predicate questions ('Are X and Y both [specific role/skill]?'), match the predicate literally against each entity's stated descriptors and do NOT let a broader umbrella descriptor satisfy it — e.g., 'multi instrumentalist', 'singer', or 'songwriter' does NOT imply 'guitarist'. A general/umbrella label is not evidence of a specific skill; treat only the exact predicate term (or an explicit near-synonym stated in that entity's own entry) as a positive match when deciding yes/no.
[m-00022] helpful=1 harmful=0 :: For 'which X has more [countable attribute]?' questions (e.g., 'which band has more members, A or B?'), emit the entity NAME, never the count. Ignore distractors: a longer/more detailed description or other passages listing members of unrelated entities (e.g., Narcissus) is not evidence — only the target entity's own explicit count decides.
[m-00023] helpful=3 harmful=0 :: For 'which of A and B satisfies predicate P?' two-entity selection questions (e.g., 'which one is in the Crassulaceae family?'), read each named entity's OWN defining entry for the target predicate value and emit the NAME of the entity whose own entry explicitly states the matching value — never the predicate value (the family/attribute name) and never yes/no. [misc-00024] helpful=2 harmful=0 :: For 'what sport are X and Y known for?' questions, emit the shared sport/category noun itself (e.g., 'tennis') as the bare token — this is the inverse of the 'what sport/occupation does X and Y participate in/do?' subtype covered by [misc-00009], where the answer is a person descriptor ('alpine ski racer'). Read the sport noun from the entity's own entry (e.g., 'professional tennis tournament') and emit it bare, with no descriptor suffix.
[misc-00025] helpful=0 harmful=0 :: For 'which [entity] is described as [descriptor clause]?' identity questions where the question embeds the descriptor clause verbatim, emit the entity NAME that is the SUBJECT of the defining appositive whose predicate verbatim-repeats that clause (e.g., 'Meatwad is a simple-minded, naïve, short attention-spanned giant anthropomorphic ball of ground meat').
